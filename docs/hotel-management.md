# 酒店管理迁出（2026-11-12）

> 本文记录当时阶段。当前已完成酒店资料分库，最新归属与限制见 [酒店分库说明](hotel-database-separation.md)。

管理员原路径与 Vue 界面保持不变。业务进程验证管理员身份并保留操作日志，再通过内部认证接口调用酒店服务。酒店服务负责管理员房型列表、实体客房筛选、每日库存与房价查询，以及每日售价修改；房量写入仍委托库存服务。

原项目没有独立的管理员房型/客房增删改接口，本次不新增这些功能。入住、退房、清洁、维修、停用房间仍与业务服务的订单和房态事务共同执行，不能宣称实体房态已经全部迁出。

酒店账号改为 sh_hotel_app：可读 hotel_info、room_type、room_type_image、room_price、room_inventory、room，只能 UPDATE room_price。不能写库存、房态或查询订单和用户。业务账号保留房价读取，撤销 room_price 的 INSERT/UPDATE/DELETE。仍是同实例同业务 schema；不是物理分库。

酒店内部接口 /internal/v1/hotel-admin/** 校验独立内部密钥，不通过网关公开；酒店服务不提供公开管理员写接口。远程失败返回 503，不直接改本地表。改价是对每日售价的绝对值赋值；若响应失败，先刷新查询实际售价。库存、订单、续住模拟支付逻辑保持不变。

## 初次配置

依赖保持启动，Java 服务停止后执行 scripts/Upgrade-HotelWrite.ps1 -DependencyHost 192.168.229.131。工具先完整备份业务库并实际恢复、核对全部表，再创建新账号、核验禁止权限、收回业务写权限并原子更新 .env。不要重复运行；已迁移环境继续使用原 Start-Cloud.ps1 / Stop-Cloud.ps1。

备份 .run/db-backups/20261112-092005-fdab4e 含完整数据库和配置快照，不能公开。数据库布局回退会同步酒店账号的读取和房价更新权限，并继续阻止业务直接写房价。退回旧单体写入布局需要停机审查权限，不能仅恢复旧 .env。
