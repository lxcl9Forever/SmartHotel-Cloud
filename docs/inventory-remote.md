# 库存写入服务

> 当前库存已独立数据库，最新账号、迁移和启动说明见 [库存分库说明](inventory-database-separation.md)。

库存写入与 Redis 投影由 `smarthotel-inventory-service`（8084）负责。业务服务保留订单、支付退款、入住流程和库存只读查询；库存服务不查询订单或用户表。

当前仍使用同一个 MySQL 实例和业务 schema，通过不同账号隔离写权限，并未拆分物理数据库。业务账号只能读原库存表，只能写自己的交接日志；库存账号只能写库存域表，不能查询订单、用户和业务交接日志。

## 一致性协议

业务事务先使用独立连接池持久化 UNKNOWN 交接日志，再调用库存 Try。预订和续住 Try 预占数量；取消、退款 Try 保留原占用。源事务提交后发送 COMMIT，回滚后发送 ABORT。库存决定与库存、操作回执、Redis 同步队列在同一事务中更新。源进程崩溃后，恢复程序对订单执行 NOWAIT 加锁读取，不能获得锁时等待下次重试，不依据超时时长释放未知占用。

最终决定暂时失败时，订单可先显示已提交，库存保持保守占用，5 秒轮询补交决定。库存服务不可用时返回失败，不回退到业务进程直接扣库存。极端故障会暂时降低可用房量，保留日志供恢复，避免超卖。Redis 使用绝对值和版本栅栏更新。

每次网络交接使用独立 attempt ID，业务操作使用稳定幂等键。先到达的 ABORT 建立撤销墓碑，可阻止迟到的 Try。零元订单合并预留与支付确认，避免同一本地事务发起两笔未完成交接。

## 已有环境切换

1. 停止 Java 服务：`./scripts/Stop-Cloud.ps1`，依赖 MySQL/Redis/Nacos 保持运行。
2. 执行 `./scripts/Upgrade-InventoryRemote.ps1 -DependencyHost 192.168.229.131`。工具备份并实际恢复校验，核对现有订单与每日 locked/sold 数量，保留所有 ID，演练数据库布局回退，再建库存账号、撤销业务库存写权限并原子更新本机 `.env`。
3. `mvn verify` 后执行原 `Start-Cloud.ps1 -DependencyHost 192.168.229.131 -Nacos`，remote 模式会启动五个服务。前端启动方式不变。

新环境先完成已有数据库拆分、酒店只读账号初始化和库存基础迁移，再执行本迁移。Compose 的完整应用布局依赖迁移生成的账号；不要只在 .env 手工写 remote 来绕过迁移。

## 备份与回退

私有备份与恢复校验报告保存在 `.run/db-backups/`，包含敏感数据和环境快照，不能上传 GitHub。SQL 18 不删除现有业务数据，但迁移含权限和外键变更，应停机操作；若中途失败保持停机并检查 manifest，不能盲目重复执行或直接恢复旧 .env。

已有数据库布局回退脚本继续保留交接日志、库存归属及操作回执，并为新布局重新配置库存账号；它仍然运行独立库存进程。切回 local 扣库存必须先清空待决交接并人工核对占用，再恢复相应账号权限，不支持仅改环境变量在线回切。

## 验证范围

自动化测试覆盖多日期原子预占、并发最后一间、重复回执、迟到 Try、撤销墓碑、预留回滚、支付/退款/续住库存转换、源事务崩溃和锁冲突、最终确认失败后的持久化重试。实际运行回归结果另记在验证记录中；模拟支付不代表真实支付宝交易已验证。
