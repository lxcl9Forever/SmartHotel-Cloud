# 订单核心边界整理（2026-11-12）

## 当前定位

现有 smarthotel-business-service 承载订单核心、支付退款、入住退房与实体房态，以及暂未拆出的营销、评价和统计。当前保留原应用名、Nacos 服务名、8082 端口、数据库和前端路径。此次是订单边界清理和约束，不是通过改名宣称已经完成订单与入住的独立进程拆分。

## 职责和事务

| 操作 | 当前本地归属 | 跨服务依赖 |
| --- | --- | --- |
| 下单、请求去重、订单详情 | 业务库订单、入住人、预订请求 | 用户目录、酒店报价、库存读取及 TCC |
| 取消、超时关闭 | 订单状态、优惠占用释放 | 库存持久释放指令 |
| 付款、退款 | 原支付/退款记录与订单状态 | 库存确认/释放；真实支付宝仍需单独配置验证 |
| 入住、续住、退房、清洁 | 订单、入住记录、实体客房状态 | 用户目录；续住计价调用酒店，新增库存走 TCC |
| 库存的数量和缓存投影 | 独立库存服务与库存库 | 容量校验调用酒店服务 |

业务本地事务不能回滚独立库存事务。订单侧持久交接日志记录待决指令，提交后发送确认、失败时撤销，暂时不可达时继续恢复。未知结果保持保守占用；不将网络超时当成库存未扣减，也不恢复跨库 SQL 降级。原 MOCK 付款和续住支付逻辑不变，真实外部交易的原子性未在本轮承诺。

## 本轮完成

- LocalInventoryCommands、LocalInventoryProjection、FreshInventoryBootstrap、旧库存 Mapper 与旧投影执行器移入 src/test。它们仅作为历史事务测试夹具，既有幂等、回滚、Redis 故障和竞争连接测试保留；生产 JAR 不包含这些实现。
- 业务进程删除无使用者的直接 Redis 增减脚本配置，旧 Lua 资源移入测试目录。维护接口只通过远程库存投影服务工作，不提供直接扣减库存的方法。
- 清除超时关单、管理查询及缓存维护中的无效库存 Mapper 依赖。支付、退款、入住等流程仍调用既有服务契约。
- application.yml 默认库存模式改为 remote；增加启动约束，直接从 IDEA 启动也不能使用 local 或未知库存模式。
- 新增架构测试：生产代码不能引用旧实现或库存 Mapper，不能出现五张库存表的直接读写 SQL；允许订单侧 inventory_tcc_journal。构建检查旧实现不在 target/classes，并检查最终打包结果。
