# 当前架构与交付范围（2026-11-13）

本版本提供可开发、可完整容器部署的智慧酒店微服务实现，保留原单体业务规则。五个后端独立进程：网关、用户、酒店资料、库存、订单业务；前端独立构建部署。四个领域各持独立数据库凭据，无跨域 Mapper/SQL 降级，共享库不包含持久化实体。

## 功能与边界

顾客注册登录、资料与常用入住人、房型日期报价、下单取消、模拟付款退款、入住续住退房、实体客房管理、促销优惠、签到、评价和运营统计沿用原有功能。用户目录、酒店报价和库存通过带内部令牌的服务接口访问。用户禁用或改密使旧令牌失效；外部网关屏蔽内部接口和伪造身份头。

业务域有意保留订单、支付退款、入住与实体房态联合事务；营销、评价和统计也是该部署单元的职责。目前不提供独立营销、支付、入住服务进程，不能将此描述为每一项功能均独立部署。若业务规模需要进一步拆分，先设计幂等操作和补偿协议。微服务边界按业务一致性划分，不按表数划分。

库存独立库通过持久化 TCC 与订单交接，保留预留归属、幂等键、待决指令和缓存投影恢复。Redis 不是订单和库存的唯一事实来源。不可确定的执行结果保守保留占用。网关连接超时 2 秒、响应超时 15 秒，上游传输故障返回 503；失败后应查询原请求结果，不能把超时当作订单未创建或直接生成新支付重试。

## 两种部署

- 日常开发：Windows 五个 Java 服务和 Vite，连接 Ubuntu 的专用 MySQL、Redis、可选 Nacos；保持现有数据与账号。
- 完整 Compose：MySQL、Redis、五个后端、前端 Nginx 共八个容器。容器通过服务 DNS 调用，默认仅向宿主回环发布入口和依赖端口。前端支持 Vue 路由刷新及网关换址解析。首次部署统一初始化四域数据库并保留私有备份、恢复演练和权限检查记录。

Compose 不要求运行 Nacos；Nacos 开发模式已经通过之前的实际服务注册和业务验收。数据库为同实例 schema 隔离，应用配置可分别连接不同实例，当前没有做跨物理 MySQL 实例迁移演练。

## 日常操作

按 README 启动和停止。排查先看 `docker compose ps`、对应服务日志、`python scripts/verify_deployment.py`，再检查领域依赖；不要通过删除卷、关闭权限隔离或信任客户端角色头修复问题。数据库迁移前停止写入应用，按各域迁移文档备份并核对待决库存指令；需要回退时按对应私有清单执行，不能直接指向旧快照继续写入。

本轮结束已恢复 Windows + Ubuntu + Nacos 开发服务，五个健康端口及前端 /、/home、/admin、/api/v1/room-types 均通过检查。隔离测试容器已停止，数据卷与私有备份保留。自动启动的前端已登记进程和启动时间，Stop-Cloud.ps1 可安全一并停止；未登记的手动前端仍在其终端按 Ctrl+C。
