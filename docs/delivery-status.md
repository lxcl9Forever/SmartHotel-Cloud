# 当前交付状态（2026-11-14）

原 business 已拆分并撤销部署单元：当前为 gateway + user/order/hotel/inventory/review/marketing/payment/stay/statistics 十个后端应用，九个独立领域 schema 和账号，Vue 前端。完整 Compose 为十三个容器。原有顾客、员工、管理员功能保留。

## 完成内容

订单服务是订单主状态唯一所有者，支付退款、实体客房与办理、营销、评价、统计均独立持有业务数据。跨服务写入改为持久工作流和库存/营销 TCC；本地业务与 Outbox 同事务、接收 Inbox 去重、版本单调和墓碑、失败退避与重放。恢复和重复请求有实际故障测试，未知结果不被伪装成失败或付款成功。

Nacos 模式下网关、Feign、可靠 HTTP 工作流和事件投递都通过服务发现；重启后按当前配置解析目的服务，未把旧实例地址作为恢复依据。默认 Compose 使用内部 DNS。各服务仅持所属库凭据，内部 API 不通过网关发布。

## 已知边界

真实支付宝/银行交易、外部 AI、生产容量压测、TLS 域名、跨机器多副本高可用和异机灾难恢复没有通过本地模拟测试宣称完成。原续住 MOCK 费用规则按用户要求保留。九库目前为同实例 schema 隔离，尚未做跨物理 MySQL 实例迁移。

事件发布目前在显式所有者表上比较事务前后变化，适合演示数据量；高吞吐部署应改为明确领域事件或 CDC。事件语义是至少一次加幂等，未声称网络恰好一次。登录页完成浏览器视觉检查，已登录页面的业务验收主要通过真实 API 完成，没有声称全流程浏览器自动化。
