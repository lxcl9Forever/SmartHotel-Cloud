# 酒店资料与房价查询边界（2026-11-12）

> 本文记录当时阶段。当前已完成酒店资料分库，最新归属与限制见 [酒店分库说明](hotel-database-separation.md)。

## 本轮完成

订单创建与展示、续住计价、顾客和员工订单列表、管理员订单详情与列表、每日秒杀、智能选房，以及业务进程保留的酒店公开兼容接口，改为通过酒店内部资料接口读取酒店信息、房型、图片及每日售价。业务中的四个对应 Mapper 已删除，入住历史不再 JOIN room_type。

业务账号对 hotel_info、room_type、room_type_image、room_price 四张表的读取及写权限已撤销。没有恢复直接查表的降级路径；酒店资料服务不可用时，依赖它的操作明确返回 503。库存、房态、订单与审计仍由各自已有边界处理。已有未支付订单取消不依赖酒店资料服务，服务中断时仍可取消。

当前仍在同一 MySQL 实例、同一业务 schema 内按服务账号隔离。库存服务设置每日房量时仍读取 room_type.total_rooms，订单和实体客房也仍有域内数据库外键关联，不能宣称酒店已物理分库。入住/退房/清洁与订单保持原事务；续住继续使用原模拟支付逻辑。

## 数据与接口语义

- 在售房型按原 sortNo 排序。历史订单按 ID 查询允许包含已停售房型；找不到的房型保留原来的空名称语义。
- 批量编号去重，单次至多 100 个 ID。顾客和员工订单列表、管理员订单列表和入住历史批量补名称；搜索与推荐批量读取相同日期范围的售价。秒杀活动拥有不同入住日期范围，维持各活动明确的区间查询。
- 房价区间为入住日期包含、退房日期不包含，按房型及日期排序。查询不补造缺失日期；下单、续住和秒杀继续使用各自原来的完整性校验与错误状态。
- 同一次单房型或单批次价格请求在酒店数据库的只读事务内查询；多个网络批次不构成全局数据库快照。已创建订单保留原金额，改价不追溯重算旧订单。没有引入跨请求缓存。
- 内部路径 /internal/v1/hotel-catalog/** 校验内部密钥，网关不开放这些路径。它们不是公开的管理员或顾客 API。
- 迁移过程中新增的入住历史 roomTypeId 仅用于内部补名，JSON 响应不暴露此辅助字段。

## 首次切换

停止 Java 服务，保持 MySQL/Redis/Nacos 启动，执行 scripts/Upgrade-HotelCatalog.ps1 -DependencyHost 192.168.229.131。先完整备份业务库并实际恢复校验，再保存权限快照、撤销业务对四张表的权限、核验酒店读权限与业务订单/库存权限，原子写入 HOTEL_CATALOG_REMOTE=enabled。

本环境成功备份与权限报告位于 .run/db-backups/20261112-100252-948088/，状态 HOTEL_CATALOG_READY。包含数据库、环境和授权快照，不可上传公开仓库。中途失败应保持停机检查报告，不能盲目重新执行。

已有数据库布局回退工具会继续保留酒店资料权限边界，回退为共享 schema 不等于把资料表访问权交回业务进程。普通启动、停止、前端运行命令不变。
